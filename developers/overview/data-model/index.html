05 — Data Model

Zod schemas in src/shared/schemas/ are canonical; this is the human-readable sketch. All IDs are ULIDs unless noted. Times inside a scenario are exercise-clock strings "H:MM" plus an optional wall-clock "09:15" for narrative.

Live sessions (scenarios/<id>/live/<sessionId>/, #407, #417)

Section titled “Live sessions (scenarios/<id>/live/<sessionId>/, #407, #417)”

The folder name is the protocol’s 128-bit SessionId (validated before it becomes a path segment). session.json is LiveSession (src/shared/schemas/live.ts): id, scenarioId, name, startedAt, endedAt?, connection { kind: 'lan', address, tls, port? } | { kind: 'relay' } | { kind: 'self-hosted', url }, joinUrlPublic (never the key fragment), attribution: 'role' | 'named', protocolVersion, lastIndex. log.jsonl is one SessionLogEntry per line in spec 0417’s format (i, at, ex?, kind, actor { kind, clientRef?, seat?, evaluator?, displayName? }, ref?, data, env? { from, seq, index? }), append-only, at most 64 KiB per line. Messages are message (text, blobIds, replyTo?, preExercise?; the actor is the seat’s clientRef and role, or the controller with its persona), message.handled, message.star (on) and message.pinned (who, text); hot wash (#415): hotwash.open { review }, hotwash.close, hotwash.item { kind, text, anonymous, questionId?, mselRowId?, objectiveId? } (the actor carries the seat and name only when not anonymous), hotwash.plus (actor: clientRef only), hotwash.retract, hotwash.update { action, itemIds, before?, after?, label?, tags? }, hotwash.promoted { id, text, memberItemIds } and hotwash.unpromoted; promoted findings are written to facilitator.json hotwash with ids starting dev-; attachments are saved under live/<sessionId>/attachments/<blobId>.<ext> and referenced by id. The writer refuses entries that carry clientId, joinToken, resumeToken, key, roots, private keys, invite URLs or addresses anywhere, strips displayName in a role session, and writes env.from as the salted clientRef, never the raw client id. Keys are never in this folder (they are in userData/live/sessions/). Inject delivery (#412) writes inject.release { releaseId, mselRowId, injectId, targets, deliveryMode, blobIds, textSha256, expectsResponse }, inject.receipt { releaseId, status, deviceAt } with the seat in actor (delivered, read, actioned) and inject.retract { releaseId }; a receipt from a seat the release was not for is an anomaly. Votes (#414) write vote.open { question, options[{id,label}], anonymous, targets, allowChange, closesAt?, mselRowId?, k }, vote.cast { voteId, optionId, changedFrom?, role? } (no clientRef; role only in a by-role vote, folded to other under k devices), vote.rationale { voteId, optionId, text }, vote.close { voteId, status: closed | interrupted, reason, results[{optionId,count}], voted, eligible, byRole? }, vote.reopen and vote.recorded { voteId, mselRowId? }; a ballot that is out of scope, for an unknown option or after close is an anomaly (vote out of scope, vote bad option, vote late) with no device reference. #417 adds attachments/, staged/, blobs.json and the summary (counts of clients, releases, receipts, messages, votes, hot wash items, observations and surveys) in session.json, written when the session ends. inject.answered { note? } (ref rowId, releaseId) records the facilitator’s Mark answered. Readers parse a line loosely (src/main/live/log-read.ts): readSlice(root, scenarioId, sessionId, { kinds?, after? }) returns rows with i, kind, at, ex?, rowId?, releaseId?, inReplyTo?, fromRoleId?, text?, the actor without displayName and clientRef, ref and data. Exports: JSON { format: 'actionstations/live-session', formatVersion: 1, session, entries }, and CSV with the columns index, at, exercise_time, kind, actor_kind, role, team, evaluator, display_name, ref_row, ref_id, summary, data_json (UTF-8 with byte order mark, CRLF, cells starting with =, +, - or @ prefixed with '). The folder name is the protocol’s 128-bit SessionId (validated before it becomes a path segment). session.json is LiveSession (src/shared/schemas/live.ts): id, scenarioId, name, startedAt, endedAt?, connection { kind: 'lan', address, tls, port? } | { kind: 'relay' } | { kind: 'self-hosted', url }, joinUrlPublic (never the key fragment), attribution: 'role' | 'named', protocolVersion, lastIndex. log.jsonl is one SessionLogEntry per line in spec 0417’s format (i, at, ex?, kind, actor { kind, clientRef?, seat?, evaluator?, displayName? }, ref?, data, env? { from, seq, index? }), append-only, at most 64 KiB per line. Messages are message (text, blobIds, replyTo?, preExercise?; the actor is the seat’s clientRef and role, or the controller with its persona), message.handled, message.star (on) and message.pinned (who, text); attachments are saved under live/<sessionId>/attachments/<blobId>.<ext> and referenced by id. The writer refuses entries that carry clientId, joinToken, resumeToken, key, roots, private keys, invite URLs or addresses anywhere, strips displayName in a role session, and writes env.from as the salted clientRef, never the raw client id. Keys are never in this folder (they are in userData/live/sessions/). Inject delivery (#412) writes inject.release { releaseId, mselRowId, injectId, targets, deliveryMode, blobIds, textSha256, expectsResponse }, inject.receipt { releaseId, status, deviceAt } with the seat in actor (delivered, read, actioned) and inject.retract { releaseId }; evaluator observations (#416) write eval.assign { clientRef, label, revision, taskCount, watch }, eval.observation (every revision: revision, kind, rating?, notes, exerciseTime, observedAt, criterionId?, capability?, ref observationId, taskId, rowId; actor evaluator label), eval.watch { clientRef, watch } and eval.ask { clientRef, text }; a receipt from a seat the release was not for is an anomaly. #417 adds attachments/, staged/, blobs.json and the summary in session.json.

Surveys (scenarios/<id>/surveys/, #422)

Section titled “Surveys (scenarios/<id>/surveys/, #422)”

Schemas in src/shared/schemas/survey.ts. Each survey is <surveyId>.json; its responses are <surveyId>.responses.jsonl, one SurveyResponse per line, append-only (a line with an id already stored replaces the earlier one when read; a line cut short by a crash is skipped). Duplicating a scenario copies the definitions, never the responses. scenario.json exports carry the definitions only. Older builds ignore the folder.

Before/after editions keep the same questions: saving one copies its sections into the other. Templates ship in surveys/templates/<templateId>.json (app resources). AppSettings.surveys.minResponses (default 3) is the anonymity threshold: below it, results show counts only. The AAR draft (#419) reads scenarioSurveySummaries() from src/main/surveys/results.ts and cites survey evidence as survey:<surveyId>:<questionId>.

Source check and plan conflicts (#423)

Section titled “Source check and plan conflicts (#423)”

Scenario.grounding.items maps an item key (row:I-07, inject:<id>, overview:<n>) to a GroundingResult (src/shared/schemas/grounding.ts):

The label shown is override ?? model ?? label. Results are kept at scenario level, not on MselRow or Inject, so an older build that strips unknown row keys loses nothing. Idea labels are in ideas.json under grounding (keys idea:<id>).

<project>/plan-conflicts.json (src/shared/schemas/plan-conflicts.ts): { formatVersion: 1, checkedAt, documents[{ id, sha256 }], stats?{ candidates, sent, skipped }, findings: PlanFinding[] }. A finding is a contradiction (slot, slot label, subject, passages a and b with document, heading path, page, chunk id and the statement’s text, the two values, the model verdict and its quotes) or a dangling_reference (passage a and the missing target), with status open / dismissed / confirmed / outdated and an optional note. Its id is sha256 of the slot and both spans (16 hex), so a re-run keeps decisions for unchanged passages.

After-Action Report / Improvement Plan (scenarios/<id>/aar.json, #419)

Section titled “After-Action Report / Improvement Plan (scenarios/<id>/aar.json, #419)”

Schemas in src/shared/schemas/aar.ts (ADR-0035). aar.json is the structured report; documents/aar.md is rendered from it in the HSEEP 2020 layout with <!-- section:name --> markers (overview, summary, ratings, findings, ip, participants, feedback, acronyms). The structured editor re-renders the table sections on save and leaves the prose sections (summary, findings, feedback) as a person edited them. History: history/aar-json.jsonl for the data, history/aar.jsonl for the document.

Sources: facilitator.json, evaluation.json, live/<sessionId>/log.jsonl (spec 0417; read by src/main/aar/sources/live-log.ts, the most recent ended session unless one is chosen; displayName is never read) and the survey store. A missing source is a gap the report states, not an error.

Plan redlines and regression drills (redlines/, drills/, #431, ADR-0048)

Section titled “Plan redlines and regression drills (redlines/, drills/, #431, ADR-0048)”

Folders created on first use; one loose JSON file per record, validated on read. Schemas in src/shared/schemas/redline.ts and drill.ts.

  • redlines/<id>.json: a proposed edit of one plan section. source (scenario, AAR finding, corrective action ids, criteria), target (document, heading path, page, sourceKind), originalExcerpt (verbatim from the ingested text), proposedText, rationale, grounding (#423), status (proposed, accepted, rejected, exported, applied, not_applied, needs_review), history, export (file, mode, sha256 of the original) and appliedCheck.
  • drills/<id>.json: a drill plan: source scenario and session, rowIds, criterionIds, correctiveActionIds with actionCriteria (the rowId|criterionId keys each action’s verdict rests on), redlineIds, expectedDocumentIds, drillScenarioId once built, and runs: per run the rating of each criterion, a verdict per corrective action, the plans’ sha256 and whether it was written to the program.
  • DocumentMeta.supersedesDocumentId: the earlier plan a document replaces. ScenarioBrief.drillOf { drillId, sourceScenarioId }: set on a drill’s scenario.

Micro-drills (micro-drills/, micro-drill-runs/, micro-drill-hints.json, #437, ADR-0057)

Section titled “Micro-drills (micro-drills/, micro-drill-runs/, micro-drill-hints.json, #437, ADR-0057)”

Created on first use; loose JSON validated on read; older versions ignore them. Schemas in src/shared/schemas/micro-drill.ts. Not the regression drills/ above.

  • micro-drills/<id>.json: a drill. annex (document, heading path, page), audience, durationMin, mode (solo or team), situation, objectives (with an optional Core Capability), steps (3 to 5; each has a prompt, expectedPoints that each cite a chunk inside the annex, three hints (Level 1 text; Level 2 text and citation; Level 3 text, citation and verbatim quote) and a modelAnswer), status (draft or ready), version, lint (the build checks’ open problems) and lintOverridden.
  • micro-drill-runs/<id>.json: a run. participants (label, optional name), assessment (model or checklist, with checklistReason), hintRule (first_miss or second_miss), withdrawnLevel3, per step the attempts (text, covered, partial, missing points, follow-up), hintsUsed and score, pausedSec, coverage.
  • micro-drill-hints.json: annex key to participant label to step id to { runs, lastHintMax, cleanRuns }, used for fading. Keyed by label, not by person.
  • ProjectSnapshot.drills (in the program folder): one summary per finished run (section, Core Capabilities, participants, minutes, coverage, hints used); no answers, no names.

Exercise program (<Name>.asprogram/, #424, ADR-0043)

Section titled “Exercise program (<Name>.asprogram/, #424, ADR-0043)”

A folder the user chooses, outside every project, for corrective actions across exercises and the multi-year IPP schedule. Schemas in src/shared/schemas/program.ts; every file is validated on read (it may be on shared storage) and loose, so a newer build’s keys survive a save.

Status lifecycle: open → in_progress → completed → verified, plus deferred and cancelled. A note is required for deferred and cancelled; verified requires a verification (drill, exercise or review). Status, history and verifications change only through program:action-status. A save carries the revision (sha256 of the file’s text) it was edited from; a stale one fails with CONFLICT and details.theirs. project.json gains an optional program: { id, path } and ScenarioBrief an optional programProposal; the AAR CorrectiveAction gains programActionId. settings.json gains program: { activePath, recent }.

Cloud privacy (#433, ADR-0031)

Section titled “Cloud privacy (#433, ADR-0031)”

The approval dialog receives an OutboundManifest (src/shared/schemas/privacy.ts) over local IPC only: the request as it will be sent, plus the original value of each redacted span. The placeholder mapping itself stays in main-process memory.

App-level files (<userData>/, never in a project)

Section titled “App-level files (<userData>/, never in a project)”
File Contents
settings.json AppSettings: recent projects, provider configs (no keys), default routing, embedding mode, UI theme, pack catalog URLs (packs.catalogs), live play defaults and remembered servers (live.defaultConnectionKind, live.servers: address, name, pinned certificate fingerprint, last test; the server key is never here)
secrets.json { [providerId]: base64(safeStorage.encryptString(apiKey)) } — ciphertext only, mode 0600. Also redaction:<key> entries: each project’s 32-byte redaction key, filed under a hash of the project id and folder path (#433)
cloud-sends.jsonl Send log for cloud requests made outside a project (#433); same lines as the project file
redaction/<key>.bin Values each project has redacted (#433), AES-256-GCM with a key derived from the project’s redaction key; <key> hashes the project id and folder path
prompts/<name>.md Global prompt overrides (project overrides live in <project>/prompts/)
models/ Downloaded local embedding models (only via the explicit download action)
provider-calls.jsonl One line per model call: provider, model, tokens, cost, duration — no prompt text, no keys
jobs.json Persisted job records so interrupted generation shows as resumable
packs/<id>/<version>/ Installed packs, verified against their pack.json hashes, read-only (ADR-0018)
settings.json regional.orgs Organization identities for regional exercises (#440): name, prefix, public signing key, fingerprint, live key. Private keys are in secrets.json as org-key-<orgId>
packs/registry.json PackRegistry: installed packs with version, enabled, source (file / url / catalog), archive and content sha256, item list (see docs/packs-format.md “Installed packs”)
packs/.staging/ Downloads and extractions in progress; emptied at every startup
templates/injects/<type>/ User inject templates, the layer between project and pack templates (ADR-0018)
live/sessions/<sessionId>.json A running live session’s secrets (ADR-0027; written by #407–#410): staff root per epoch, controller signing and ECDH keys as JWK, last seq; safeStorage ciphertext only, deleted at session.end. Never in a project folder
live/lan.log (+ .1–.3) The LAN session server’s connection log (#407, ADR-0032): time, event, remote address, client id, close code; fixed fields, never a frame, a query string or a key. Rotated at 5 MB × 3

SimCell personas and drafts (#429)

Section titled “SimCell personas and drafts (#429)”
File Contents
scenarios/<id>/personas.json PersonasFile (src/shared/schemas/persona.ts): version: 1 and up to 20 PersonaCards. Optional: a scenario without it loads as before. A card holds displayName (a fictional person or a title), roleTitle, organization {name, fictional}, kind, register (style only, 40 characters), goals, deadlines {at, wants, ifMissed}, escalationRules {when, then} (when is time, row_released, no_reply or player_says), knowledge {knows, doesNotKnow, mustNotReveal}, concessions {give, onlyIf}, hardQuestions, linkedRowIds, channels, voice {providerId, voiceId, postFx} and source.simcellScriptIndex. Included in history snapshots and in the facilitator part of the distribution ZIP as personas.md, never in players/.
scenarios/<id>/live/<sessionId>/simcell.jsonl One SimcellDraft per line, appended each time a draft is created and again when it is resolved (the last line per id wins). Controller side only. Holds the draft, its applied ids, flags, providerRef, status (queued, sent, edited, rewritten, discarded) and finalText.
scenarios/<id>/live/<sessionId>/calls/*.wav Call recordings, only while “Keep call recordings” is on for the session; otherwise deleted once transcribed.
scenarios/<id>/media/_calls/*.wav Rendered voice lines for calls and previews.
scenarios/<id>/facilitator.json simcell SimcellExchange[]: what a player said and the approved reply, from the offline mode, for the hot wash.
settings.json simcell.capability { "<providerId>/<model>": { level, passed, failed, checkedAt } }, the model check result per provider and model.

The session log (log.jsonl) gains simcell.draft (draft text, final text, checks, whether edited), call.ring, call.answer (text or transcript, audio size, never the audio) and call.end.

Regional exercises (scenarios/<id>/regional.json, #440)

Section titled “Regional exercises (scenarios/<id>/regional.json, #440)”

RegionalState (src/shared/schemas/regional.ts): exercise id, role (host or participant), this organization, the organizations with their pinned keys, frame version, received slice revisions, sharing settings, cross-organization channels, proposals and the revisions this computer last exported. MselRow, Inject and Role gain optional owner, revision, visibility, publicSummary, dependsOn; Scenario.regional points at the file. Single-organization scenarios are unchanged. Bundle format: exercise-bundle-format.md.

Hazard snapshots (hazards/, project.json location, #439, ADR-0061)

Section titled “Hazard snapshots (hazards/, project.json location, #439, ADR-0061)”

src/shared/schemas/hazards.ts.

  • project.json location: label, lat, lon (full precision), optional stateFips and countyFips, sendPrecision (0.01 or 0.1). Only values rounded to sendPrecision are sent.
  • hazards/index.json: active (the snapshot ideas use) and the list of snapshots (id, label, fetchedAt, pinned). At most 10 snapshots; pinned and active ones are not dropped.
  • hazards/<id>.json: a snapshot. request (rounded values sent), sources[] (id, request URL with any key replaced by <MAP_KEY>, status ok / empty / error / skipped, HTTP status, attribution, access time), and the normalized records: alerts, forecast, earthquakes (recent, historical), fires, declarations, infrastructure (imported layers). Raw responses are not kept.
  • scenario.brief.hazardSnapshotId and the idea’s hazardSnapshotId name the snapshot a scenario was written with. settings.json hazards.enabled is the opt-in switch; the FIRMS key is in secrets.json under firms, as ciphertext.
