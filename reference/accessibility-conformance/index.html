Accessibility Conformance Report: Action Stations

VPAT 2.5 Rev, Revised Section 508 Edition (WCAG 2.2 Level A and AA, Revised 508 Chapters 3, 5 and 6)
Product Action Stations (machine name actionstations)
Version evaluated 0.6.2
Report date 2026-11-02
Product description A local-first desktop application (Electron) that generates tabletop exercises, with a phone, tablet or laptop web page for live-play participants and exported PDF, Word and Excel documents
Contact for accessibility problems Open an issue at github.com/actionstations-ai/actionstations
Template ITI VPAT 2.5 Rev (508 edition). This is the vendor’s own evaluation, not a third-party audit.

Scope: three products evaluated separately

Section titled “Scope: three products evaluated separately”
Product What it is How it was checked
Desktop app The Electron application on Windows, macOS and Linux (the renderer, a React web UI in a Chromium window) Automated accessibility tests of every screen, scripted keyboard and layout checks, color contrast check
Player page The web page participants open in a browser during live play (served by the facilitator’s computer or a relay) Automated accessibility tests of every screen, in light and dark
Exported PDFs PDFs the app writes: briefing, handouts, player injects, MSEL, inject deck, handbook, EEG packet, survey forms, AAR/IP, inject media PDFs, and large-print copies Tagged-PDF output on every export, structure checks; see the Translation and accessibility guide

Word (.docx) and Excel (.xlsx) exports, the project website, and the guides are not evaluated in this report (see “Not evaluated” at the end).

Terms

Section titled “Terms”
  • Supports: the functionality meets the criterion with no known defects, on the evidence listed.
  • Partially Supports: some functionality does not meet the criterion, or the criterion has only been partly evaluated. The remarks say which.
  • Does Not Support: the majority of functionality does not meet the criterion.
  • Not Applicable: the criterion is not relevant to the product.

Evaluation methods used

Section titled “Evaluation methods used”
  1. Automated: axe-core accessibility tests, with the tags wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa and best-practice.
    • Desktop: an automated test audits every screen in light and dark mode against a seeded project (documents, a scenario with rendered injects, packs, live connection, settings) and fails on any violation.
    • Desktop: a second automated test covers the criteria axe cannot test (text spacing, content on hover or focus, focus not obscured, pointer cancellation, dragging alternatives, target size, consistent help) on 16 screens.
    • Player page: an automated test audits every screen in light and dark, on a phone viewport, at 100 % and 200 % zoom, plus the end screen.
  2. Scripted keyboard and layout checks alongside those tests: visible focus on every tab stop, no keyboard traps, dialogs take focus, close on Escape and return focus, a keyboard-only walkthrough (new project to export; for the player page, joining), a 200 % zoom check that no control is clipped or unreachable, no horizontal scroll, and targets of at least 24 px on the player page. Empty and error states are checked for next-step text.
  3. Contrast check: a script tests every design-token color pair the renderer’s stylesheets use, in light and dark, at 4.5:1 for text and 3:1 for UI boundaries and focus rings. The player page imports the same tokens.
  4. PDF checks: Chromium’s tagged-PDF output is switched on for every export. An automated test checks the language tag and tagged structure of the Spanish packet, injects and survey form. A script can run veraPDF (PDF/UA-1) on exported PDFs when veraPDF is installed. No veraPDF run is recorded, so PDF/UA conformance is not claimed.
  5. Design review of the accessibility requirements for the player page and for player translation.

Not done: no recorded testing with a screen reader (NVDA, JAWS, VoiceOver, Narrator), screen magnifier, speech-recognition software or switch device; no usability testing with people with disabilities; no third-party audit. Automated tools find only part of the WCAG failures, so “Supports” below means “no defect found by the checks above and none known”, not “verified with assistive technology”.

Known exceptions

Section titled “Known exceptions”
Item Product Criteria Status
Exported PDFs are fixed-layout pages (Letter size). They do not reflow at 320 px or 400 % zoom. A large-print copy (18 pt, one column) is offered for the briefing, handouts and player injects only. Exported PDFs 1.4.4, 1.4.10 By design.
PDF/UA conformance has not been tested. Text generated by CSS (page numbers, the stamp) is not tagged. Running headers and footers are page text and may be read on every page. Exported PDFs 1.3.1, 4.1.2, 504.2.2 Known limits of Chromium’s PDF writer.
AI-generated video clips have no audio description. Video has captions only when the inject has voice lines. Player page, desktop, media 1.2.2, 1.2.3, 1.2.5 Open.
No person has tested the desktop app, the player page or the PDFs with a screen reader and recorded the result. The Translation and accessibility guide asks users to check a packet with VoiceOver or NVDA. All Several; see the tables Open.
Map pin placement is by clicking the plan; a keyboard alternative has not been checked. Desktop app 2.1.1, 2.5.1 Not evaluated.
The app’s own screens are English only. Player material (briefing, handouts, injects, participant surveys) can be exported in Spanish after a person reviews the translation. All None (3.1.1 and 3.1.2 are met) Listed for buyers who need other interface languages.

Not evaluated

Section titled “Not evaluated”
  • Word (.docx) and Excel (.xlsx) exports.
  • The project website and the published copies of the guides.
  • Installers and operating-system dialogs (file pickers, keychain prompts).
  • The self-hosted server and relay (their only user interface is the player page they serve).
  • Third-party packs and templates.
  • Behavior with specific screen readers, magnifiers, speech recognition and switch access.

How to check this yourself

Section titled “How to check this yourself”
  • Desktop app and player page: open every screen with the keyboard alone, zoom to 200 %, and run an accessibility checker such as axe in light and dark mode.
  • PDFs: run veraPDF on an exported packet; open a packet with VoiceOver or NVDA and list headings.
